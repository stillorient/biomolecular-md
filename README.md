# biomolecular-md

生物分子 MD 的 agent skill：先完成体系适配评估和力场选择，再生成可审查的具体参数计划，经用户确认后执行。

适用于蛋白–多肽、蛋白–蛋白等生物分子体系的新模拟设计、体系变更和历史流程审查。通用的是决策过程；力场、溶剂、离子、处理方式、采样和分析都需要针对当前体系论证。

## 工作流程

1. 核实当前结构、序列、构建体、化学连接、端基、质子化、必要组分、环境和研究目标。
2. 对完整模型组合查证：参数覆盖、相关实验与独立基准、已知偏差、版本匹配的引擎实现。
3. 生成 **A：体系与模型决策卡**，记录选择、依据、验证方法和失败处理，交用户确认。
4. 完成具体适配，生成 **B：MD 参数与计划卡**，覆盖准备、数值设置、阶段、生产、分析、恢复和预算。
5. 核对参数是否落实到代码，记录静态验证、实际建系、科学适用域与授权各自的状态。仅执行用户已确认的范围。

新体系从当前输入重新评估，不继承其他案例的参数或确认。相同的数值也需要当前体系的依据；缺少参数、化学身份或实现支持时，应明确交付缺口与补证方案。

## 安装与使用

将本仓库克隆到你的 agent 支持的 skill 搜索目录中，目录名保持为 `biomolecular-md`：

```text
git clone https://github.com/stillorient/biomolecular-md.git <你的-skill-目录>/biomolecular-md
```

也可以让 agent 直接读取本仓库的 [SKILL.md](SKILL.md)。在支持命名 skill 的环境中，可以这样提出任务：

```text
使用 $biomolecular-md 评估这套蛋白–多肽体系。
先核实体系与候选完整力场组合，生成 A 卡；确认后生成 B 卡。
每项选择给出依据、验证与不适用时的处理。当前只做方案，不运行 MD。
```

提供实际结构、完整序列/构建体说明、研究问题、实验环境与资源约束。缺少的信息可以先标为未知，不能自动用默认处理替代。

## 辅助脚本

脚本仅使用 Python 3 标准库，不调用分子计算引擎。

```text
python scripts/new_system.py init --system-id my-complex --input <结构文件> --input <序列或说明文件> --out <新的计划目录>
python scripts/new_system.py check <计划目录>/adaptation.json
python scripts/check_timing.py --help
```

`init` 创建绑定当前输入指纹的空白评估表、两张卡及交接记录，不生成默认力场、数值配置或运行批准。`check` 核对声明的文件哈希、参数依据覆盖和实现证据绑定；未完成的交接返回退出码 2。记录格式见 [交接检查工具](references/new-system.md#交接检查工具)。

`check_timing.py` 只校验步长、步数、时长和输出间隔的算术关系。两种工具都不能代替科学判断或用户授权。

## 能力与验证范围

这是面向 agent 的决策与适配工作流，附带文件级辅助工具。仓库不包含通用 MD 引擎、力场参数包、模型权重、案例结构或案例专用生产驱动。执行真实模拟仍需适配目标引擎、验证当前体系，并取得相应范围的确认。

开发中对公开体系 1YCR 和 1BE9 的独立案例实现做过非运行工程检查；这些外部案例及其报告不随本仓库分发。案例通过不代表任意新体系适用，也不代表已验证力场科学准确性。真实建系、最小化和 MD 未在这些非运行检查中执行。

文献索引保留查阅范围与局限。实际使用时应核对当前体系、具体参数发行版和引擎版本，不将索引当作固定推荐排名。
