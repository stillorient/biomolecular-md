# 新蛋白–多肽体系：重新评估、选择与交接

在第一次处理一个体系，或序列/构建体、组装体、化学连接、环境、问题/目标量改变时使用。已有输入相同也可能因研究问题改变而需要新评估。可以复用经过核验的通用代码与原始文献，不能继承另一个体系的科学结论、参数或运行确认。

## 从当前输入开始

在实际项目目录创建新的计划目录，保留原始结构、序列、构建体说明及其来源/哈希。没有项目归属的 skill 演练才放在 Codex 资源目录。使用 [new-system-assessment.md](../assets/new-system-assessment.md)；也可用文末工具生成空白 A/B 与工作表。工具不解析化学，不选择力场，不读旧案例配置。

1. 明确研究问题与主要观测量，再检查原始结构和完整序列。结构格式可能是 PDB 或 mmCIF；保留 entity、auth/label 编号、插码、组装变换与模型号，不假定 A/B 两链。确认受体/伙伴角色和实际构建体，不从长度猜测。
2. 按 [体系适配规则](system-fit.md) 独立核实端基、缺失区/重原子、二硫键/环化、手性、非标准骨架、糖/膜/金属/辅因子/结构水及关键质子化。结构文件没记载的化学状态可能仍需序列/合成说明支持；未知不能标成不存在。
3. 将每项写为已确认事实、明确的建模假设或未知，并指向当前输入或用户说明。环境未给出时提出有依据的候选，留待 A 确认。关键身份/连接/必要组件未知时，完成其余评估并集中询问；不以默认封端、删组件或自动补全掩盖。
4. 列出所有触发分支的交集。例如“柔性 + 环化 + N-甲基”需同时评估构象平衡、闭环和非标准扭转；“折叠蛋白”不能覆盖肽的化学特征。没有结构/序列时可以交付资料需求与评估框架，不能虚构具体模型和运行参数。

## 为当前体系重新查证和选型

[证据索引](evidence.md) 是查证入口，不是候选排名或固定套餐。对每个关键特征/目标量做有界检索，记录查询词、日期、来源、实际读到的范围及未找到证据的结果。优先原始开发研究、独立基准及版本匹配的官方实现文档。

| 检索层 | 需要回答的问题 | 可组合的检索词示意 |
|---|---|---|
| 化学覆盖 | 实际残基、连接、末端、手性与特殊组件是否覆盖？ | 当前具体修饰/连接 + parameterization / force field validation |
| 构象与相互作用 | 折叠/无序、结合伴随折叠、界面电荷等是否在验证域内？ | 当前构象/相互作用类别 + benchmark + experiment |
| 主要观测量 | 目标是接触、构象分布、相对自由能还是动力学？证据是否直接相关？ | 目标量 + 体系类别 + independent validation |
| 反证 | 是否存在过度缔合、尺寸/二级结构、离子/配位或采样偏差？ | 模型名 + 关键特征 + bias / failure / overbinding |
| 实现 | 精确发行版、参数包、特殊项、水/离子与数值约定是否保持？ | 选定引擎/版本 + 完整参数包 + official documentation |

阅读后填候选比较表：完整模型组合、化学覆盖、最接近的验证体系/环境/量、直接支持与外推、反证、引擎支持、关键检验、保留/排除理由。实际有价值的候选才列；只有一个合理候选时解释原因，不为凑数强迫双力场。没有相关独立基准就记录这个缺口；不能用多个转载网页制造多角度证据。

模型组合包括蛋白/肽、水、离子、其他组分、连接/补丁、特殊非键项与实现版本。选中的可以恰好与旧案例相同，但理由必须来自当前特征和目标量。先形成 A 的建议、合理替代、外推边界和判断，再生成 B；明确授权的非运行演练可连续生成两张未确认草案。化学或方法仍受阻时 B 写验证/补证计划，不伪造生产方案。

## 由选定模型重新推导 B

按 [protocol.md](protocol.md) 填具体值和验证，以下项目都重新决定，不从 1YCR/1BE9 的 JSON 作为默认起点：

- 清洗/保留、端基/缺原子修复、质子化/微观状态、构象与重复来源；每个处理保留身份映射。
- 环境、边界、盒型/大小与自镜像风险、中和/盐浓度定义及水/离子实现；盒尺寸由当前构型和预期运动决定。
- 精确力场非键约定、积分/约束/HMR、热压控制、需要的准备/平衡/释放阶段；跨引擎不能只抄相同数值。[E05–E07, E25]
- 主要分析量、参考/原子选择、输出周期、平衡剔除、采样与不确定性；重复数、长度和延长规则服务于目标量，不能默认为 3 次或 100/200ns。
- 资源/容量、全部条件和允许延长、恢复策略、停止和失败处理；不默认 30/40GB、某台 GPU、2 份 checkpoint 或相同验收窗口。

用当前具体配置逐字段形成 `parameter_decisions`：字段路径、所选值的哈希、当前体系范围指纹、选择来源（本次新决定/重新评估的旧决定）、资料定位、当前体系理由、验证和失败动作。合理的相同值可以保留；没有理由的复制不能通过交接。项目预算可由用户约束支持，不必为每个工程值虚构论文。

## 实现能力与静态交接

先检查目标执行器支持的化学、完整参数组合、数值方法、阶段/输出和分析语义。通用驱动应从当前配置读值；仅验证过案例的驱动需在当前项目内适配和测试。不能以改 ID/删除验证/替换成旧水模型消除拒绝。

每个具体配置字段都要映射到消费它的函数/引擎选项和可核查测试；不支持的字段明确拒绝。代码尚未实现时给出完整可审查规格与实现缺口，不宣称可以运行。遵循 [execution-contract.md](execution-contract.md)，用当前体系做以下适用检查：

- 从当前输入生成身份映射、化学图/模板覆盖证据；核对端基、特殊连接、组件、净电荷和虚拟位点。无 MD 授权时先审查准备 API 副作用。
- 用参数扰动验证消费逻辑或拒绝：例如换盒规则/离子/输出周期/步长/阶段/选择后，实际解析对象或调度应变化；不能只检查配置里数字不同。
- 对实际共享生产调度做假引擎恢复/超时/预算测试，对当前观测量用已知几何的合成数据测试。非运行时不调用真实 Context、能量/力、内部最小化或积分。
- 记录当前配置、代码与验证文件的哈希；输入/模型/代码改变使对应证据失效。报告计划具体性、静态覆盖、真实建系、科学适用域和授权五种状态。

若需要受支持的新方法/组件，应实现相应分支并验证，或明确停止在计划阶段。通用 skill 不承诺每个新体系都能走到生产；识别不适用并给出最小补救方案也是有效结果。

## 交接检查工具

`scripts/new_system.py` 是标准库文件工具，只有 `init` 和 `check`，没有运行引擎、网络或提交计算入口。

```text
python <skill>/scripts/new_system.py init --system-id <新体系ID> --input <结构文件> --input <序列或说明文件> --out <新的计划目录>
python <skill>/scripts/new_system.py check <计划目录>/adaptation.json
```

`init` 要求至少一个真实存在的输入文件；拒绝覆盖已有目录，只生成当前输入指纹和空白工作表/A/B，没有数值配置、选定力场或确认。随后由本次评估填写工作表和卡，再人工/代码生成当前体系的 `parameters.json`。该 JSON 只放需落实的配置，不放旧报告或确认记录。

`adaptation.json` 的填写约定：

- `assessment`、`cards.A/B`、`configuration`：填写文件 `path` 与实际 `sha256`。相对路径以记录目录为基准；配置必须是 JSON 对象。工作表包括事实、检索与候选取舍；工具不自动判断这些科学内容的真实性。
- `parameter_decisions`：配置的每个叶字段（JSON Pointer，例如 `/stages/0/dt_fs`）一条。包含 `pointer`、`value_sha256`（规范 JSON 值的 SHA256）、`scope_sha256`、`decision_context_sha256`（绑定当前输入、工作表与 A 卡）、`origin`（`new_decision` 或 `reassessed`）、`previous_source`（重新评估时必填）、`source`、`rationale`、`validation`、`failure_action`。工具报告各个预期哈希，但填写哈希不代替实际评估。不适用项也显式赋值并解释。不能靠声明 `approved: true` 替代。
- `implementation.status`：`not_assessed` / `unavailable` / `adapted`。前两种会报告实现缺口，不阻止完成科学计划。`adapted` 时 `files` 给出当前代码文件及哈希；`coverage` 每字段包含 `pointer`、`consumer`、`evidence`（文件/哈希）和 `context_sha256`。后者绑定当前输入/评估/A/B、配置哈希及代码文件表；脚本报告预期值。证据文件应包含实际静态/合成测试结果、相应参数的消费/拒绝断言和禁止调用记录。

工具分别报告 `parameter_provenance_complete` 与 `static_handoff_complete`，发现旧范围/输入指纹、缺少字段依据、改值后未复审、实现覆盖遗漏、代码/证据变化时失败。它不运行证据文件、不验证论文结论、不对语义内容打分，也不能识别被刻意伪造的来源；仍须人工核对 A/B 与实际配置/测试内容。即使检查通过也始终输出 `runtime_authorized: false`。真实确认按 skill 主流程另存，绝不从该文件继承旧确认。
